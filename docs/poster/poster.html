Disponible ≠ sano

Detección de degradaciones en una API mediante monitoreo con Prometheus y Grafana

Ana Sena · Francisco Lima · Nicolás MárquezNoviembre 2026

1Objetivo e hipótesis

¿Cómo detectamos que una API tiene problemas de rendimiento o errores aunque siga disponible?

Hipótesis: las señales RED (Rate: tráfico · Errors: tasa de errores · Duration: latencia en percentiles) revelan degradaciones que un health check no ve.

El health check solo pregunta “¿responde?”.

5Conclusiones

  • Hipótesis confirmada: ambas degradaciones se detectaron en menos de 90 s con la API “disponible”.
  • Alertar por percentiles y tasa de errores, nunca por promedio ni por estado binario.
  • Validar la instrumentación: etiquetas correctas, cardinalidad acotada, buckets cerca del umbral.
A favorEstándar abierto (CNCF), PromQL potente, detección de caídas incluida (pull), todo como código.
LimitacionesPercentiles aproximados, un solo nodo, cardinalidad delicada. Dicen qué y dónde, no por qué.
