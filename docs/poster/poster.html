Disponible no significa sano

Cómo detectar una API que falla sin caerse

Objetivo: descubrir cómo detectar que una API tiene problemas aunque siga respondiendo.

Hipótesis: medir tráfico, errores y latencia (las señales RED) lo revela.

¿Qué es una API?

La “puerta” por la que un programa le pide datos a otro. Ej.: la app del banco consultando tu saldo.

¿Cuál es el problema?

El chequeo de salud de la API responde “200 OK”: todo parece estar bien.

Pero 1 de cada 4 usuarios espera más de un segundo por una respuesta…

¡…y a otros les llega un error, aunque el monitor siga en verde!

¿Cómo lo probamos?

k6 envía el mismo tráfico constante a una API hecha en Node.js.

Le provocamos fallos a propósito: lentitud en un escenario y errores en otro.

Prometheus mide las señales y avisa; Grafana las muestra en un panel.

¿Qué encontramos?

200 OK siempreEl chequeo de salud no vio ninguno de los fallos.

p95: 1,4 sLa alerta de lentitud sonó a los 75 s. El promedio no habría avisado.

12 % de erroresLa alerta de errores sonó a los 85 s.

Lo que aprendimos

Disponible ≠ sano

Hay que medir tráfico, errores y latencia, no solo si la API responde.

Mirar percentiles

Alertar por el p95 y el % de errores, no por el promedio.

Validar las métricas

Un error en una etiqueta llegó a ocultar todos los errores.
