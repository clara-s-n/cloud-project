Instrumentación

Un middleware, dos métricas, tres etiquetas

// al terminar cada respuesta

res.on('finish', () => {

  const route = req.route

    ? req.baseUrl + req.route.path // /api/products/:id

    : 'unmatched';

  labels = { method, route, status_code };

  httpRequestsTotal.inc(labels);

  httpRequestDuration.observe(labels, secs);

});

Cardinalidad

La etiqueta lleva la plantilla /products/:id, no la URL real. Con la URL, cada id crearía una serie nueva.

Error que encontramos

Los 500 inyectados salían como route="unmatched" y el filtro /api/.* los ignoraba: la alerta de errores nunca se disparaba.

Proyecto final · Cloud Computing
[Ana Clara] — 5:20 a 6:20. Explicar el middleware. Dos lecciones. (1) Cardinalidad: cada combinación de etiquetas es una serie temporal en memoria; nunca poner ids, usuarios ni URLs completas. (2) Contar el bug real: en la primera corrida el escenario de errores devolvía 12 % de 500, k6 lo veía, pero Prometheus mostraba 0 %, porque el middleware de caos respondía antes de que Express resolviera la ruta. La observabilidad también puede fallar en silencio: hay que validar las métricas contra una fuente independiente (aquí, k6).
